# Changelog

Все значимые изменения проекта документируются в этом файле.

Формат основан на [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/),
проект придерживается [семантического версионирования](https://semver.org/lang/ru/).

## [0.3.0] - 2026-06-03

Многоустройственные API-ключи со сроком жизни, настраиваемые повторы воркера и документация по HTTPS-доступу к хранилищу.

### Безопасность

- Ключи на устройство: каждый вход (`login`, `register`) выдаёт отдельный ключ и **не сбрасывает** остальные сеансы. Хранятся в новой таблице `api_keys` (хеш, метка, время последнего использования, срок истечения).
- Срок жизни ключа задаётся `AUTH_API_KEY_TTL` (по умолчанию 30 дней). Окно скользящее: использование продлевает ключ, просроченные ключи отбрасываются при аутентификации.
- Управление ключами: `GET /auth/keys`, `PATCH /auth/keys/:id` (метка), `DELETE /auth/keys/:id`, `POST /auth/logout` (текущий сеанс), `POST /auth/logout-others` (все, кроме текущего).

### Добавлено

- Настраиваемые повторы фоновых задач: `WORKER_MAX_RETRIES` и `WORKER_RETRY_TIMEOUT`.
- Извлечённый текст файла (`text_content`) в ответе `GET /files/:id/info`.
- Автоматическая метка устройства для ключа по заголовку `User-Agent` (можно переименовать).
- Документация: доступ к S3 по HTTPS на том же домене через префикс пути + пример конфига `deploy/nginx.example.conf`; секционные разделители в `.env.example`.

### Изменено

- `url_status` переведён с `TEXT` на тип-перечисление (`ENUM`).
- Удалён эндпоинт `POST /auth/refresh` — ротация единственного ключа заменена управлением ключами на устройство.

### Исправлено

- Автотегирование: выключенные стоп-слова снова могут становиться тегами — фильтр `active_stopwords` теперь учитывает признак `is_enabled`.

## [0.2.0] - 2026-05-30

Усиление безопасности и исправление обработки задач воркера.

### Безопасность

- API-ключи хранятся в виде SHA-256-хеша, генерируются через CSPRNG, не пишутся в логи и не возвращаются в `GET /auth/me`.
- Ротация ключа при входе: `login`, `register` и `refresh` выдают новый ключ один раз.
- Защита от SSRF при загрузке URL: блокировка приватных, loopback, link-local и CGNAT-адресов на этапе соединения, белый список схем, ограничение редиректов и размера ответа.
- Ограничение частоты запросов (rate limiting) на `/auth/login` и `/auth/register`.
- Параметризация вызова `active_stopwords`, белый список столбцов в `ORDER BY`, переход на `ILIKE` с экранированием подстановочных символов.
- Устранён timing-oracle при проверке учётных данных.

### Добавлено

- Поле `url_status` (`pending`/`ready`/`error`) у заметок-ссылок.
- Эндпоинт `GET /files/:id/info` и поле `updated_at` в ответе файла.
- Заголовок `Authorization` принимает значение как с префиксом `Bearer`, так и без него.

### Изменено

- Воркер логирует ошибки задач (обработчик ошибок asynq + корневая ошибка обработки PDF).
- Swagger UI перенесён под `/api/v1`.

### Исправлено

- Удаление NUL-байтов (`0x00`) из извлечённого текста PDF и URL — PostgreSQL отклонял такие значения.
- Пробелы между словами при извлечении текста из веб-страниц.
- Автотегирование заметок-ссылок (учёт извлечённого содержимого) и инвалидация кэша списка тегов.
- Сбой постановки задачи при загрузке файла больше не оставляет «сиротливые» записи в БД и объекты в хранилище.
- Логирование ошибок удаления объектов из S3.

## [0.1.0] - 2026-05-28

Первый публичный релиз.

### Добавлено

- Текстовые заметки в Markdown, заметки по ссылке (URL) и загрузка PDF-файлов.
- Полнотекстовый поиск по всему содержимому с префиксным поиском и ранжированием.
- Автоматическая и ручная тегизация; управление тегами и стоп-словами (RU/EN).
- Фильтрация по тегам, сортировка, пагинация.
- Корзина с восстановлением и безвозвратным удалением.
- Хранение файлов в S3-совместимом хранилище (Garage), доступ по presigned-ссылкам.
- Аутентификация по API-ключу.
- Веб-интерфейс: светлая/тёмная тема, локализация (RU/EN/JA), адаптивная вёрстка.
- Развёртывание через Docker Compose.
